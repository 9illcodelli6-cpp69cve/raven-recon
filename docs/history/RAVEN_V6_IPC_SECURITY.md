# RAVEN V6 — IPC Security

## Communication Architecture

RAVEN V6 is a local desktop application. Component communication uses:

| Channel | Type | Security |
|---------|------|----------|
| Python Control Plane → PolicyGate | In-process function call | No network; Python objects |
| Python → Rust (future) | PyO3 FFI / compiled .pyd | In-process; no TCP |
| Python → C++ analysis | pybind11 .pyd | In-process; no TCP |
| Python → Scheduler | In-process call | No network |
| Python → DB (SQLite) | sqlite3 module | Local file; no network |
| Python API → UI | Local HTTP (127.0.0.1 only) | loopback only |

**No TCP control plane between RAVEN components exists.**
**No network transport encryption is needed or implemented.**
This is documented as: `NETWORK TRANSPORT ENCRYPTION: NOT APPLICABLE`

---

## Rust IPC (Source Present / Build Blocked)

The Rust workspace defines typed IPC messages:

```
raven-ipc/src/message.rs   — typed ActionRequest/ActionDecision DTOs
raven-ipc/src/session.rs   — SessionToken (SHA-256 of 2 random UUIDs)
```

When compiled, Python would communicate with Rust via:
- Option A: PyO3 extension module (preferred — in-process, no socket)
- Option B: Windows named pipe with OS ACL (RAVEN user only)

Named pipe ACLs on Windows restrict access to the current user account.
No network socket is planned for Rust–Python communication.

**RUST_RUNTIME_BLOCKED** — build requires rustc/cargo (not installed).

---

## Session Token

Session tokens are defined in `raven-ipc/src/session.rs`:
- Generated: SHA-256 of two random UUIDs
- Short-lived: scoped to session
- Not logged to audit (secret values)
- Not target-controlled: generated by RAVEN, not from target responses

---

## Replay Protection

In-process calls have no replay window.
Named pipe calls: message IDs/nonces defined in schema (not yet compiled).
TCP: NOT APPLICABLE (no TCP control plane).

---

## Local API Server (UI Bridge)

`raven/api/server.py` exposes a local HTTP API for the UI:
- Binds: 127.0.0.1 only
- Host validation: rejects non-localhost Host headers
- Origin validation: CORS restricted to localhost origin
- CSRF/session token controls: session token in header required

---

## Policy via IPC

When a Python action request crosses the IPC boundary to Rust:
- Request: typed `ActionRequest` DTO (versioned schema)
- Decision: typed `ActionDecision` DTO
- Incompatible schema version: rejected with structured error
- Malformed request: DENY (fail-closed)
- Unknown capability: DENY (fail-closed)
